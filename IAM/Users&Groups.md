# AWS IAM — Creating Users and User Groups

**AWS Certified Cloud Practitioner · Study Notes · October 2026**

## 1. What is AWS IAM?

**IAM (Identity and Access Management)** is an AWS service that controls who can access AWS resources and what actions they can perform.

IAM helps us manage:

* **Users:** Identities for people or applications that need access.
* **Groups:** Collections of IAM users with shared permissions.
* **Policies:** Documents that define allowed or denied actions.
* **Roles:** Identities that provide temporary permissions to trusted users or services.

**Example:** In a company, developers might need access to EC2 and S3, while finance employees might only need access to billing information.

## 2. IAM Is a Global Service

IAM is a **global AWS service**, meaning you don't select a specific AWS Region when creating IAM users or groups.

* IAM users can access resources across different AWS Regions, subject to their permissions.
* IAM users and groups are managed from the IAM console.
* Other services, such as EC2, have region-specific resources.

| Service    | Type     | Explanation                                |
| ---------- | -------- | ------------------------------------------ |
| IAM        | Global   | No Region selection required               |
| Amazon EC2 | Regional | Instances are created in a selected Region |

## 3. Root User vs IAM User

When you initially create an AWS account, you use the **root user**.

| Feature           | Root User                                          | IAM User                                        |
| ----------------- | -------------------------------------------------- | ----------------------------------------------- |
| Created when      | AWS account is created                             | Created by an administrator                     |
| Access            | Full account access                                | Depends on assigned permissions                 |
| Permissions       | Cannot be restricted using identity-based policies | Can be granted specific permissions             |
| Recommended usage | Account setup and tasks requiring root access      | Routine administrative or other permitted tasks |

**Best practice:** Avoid using the root user for everyday tasks. Use an appropriately permissioned identity instead.

For production environments, AWS generally recommends federated access through IAM Identity Center rather than creating long-term IAM users for every employee.

## 4. Creating an IAM User

Example username: `siddharth-admin`

### Step 1: Open IAM

1. Search for `IAM` in the AWS Management Console.
2. Open the IAM dashboard.
3. Navigate to **Users → Create user**.

### Step 2: Enter the Username and Configure Console Access

1. Enter a username.
2. Enable AWS Management Console access if required.
3. Choose IAM user when following this hands-on exercise.
4. Select a password option.

### Step 3: Configure the Password

Two options are available:

| Option                 | Meaning                            | Typical use                          |
| ---------------------- | ---------------------------------- | ------------------------------------ |
| Custom password        | You choose the initial password    | Setting up your own learning account |
| Autogenerated password | AWS generates the initial password | Creating accounts for other users    |

When creating an account for another person, enable **Users must create a new password at next sign-in**.

This allows the user to replace the initial password with one they control.

**Note:** Autogenerated passwords are not inherently more secure than strong custom passwords. They primarily simplify account setup.

### Step 4: Assign Permissions

1. Choose to add the user to a group.
2. Create or select the `admins` group.
3. Attach the `AdministratorAccess` policy to the group.

### Step 5: Review and Create

1. Verify the username and permissions.
2. Optionally add tags.
3. Click **Create user**.
4. Save the sign-in information securely.

## 5. IAM User Groups

An **IAM group** is a collection of IAM users. You attach policies to the group so its members inherit the permissions granted by those policies.

### Example

```text
IAM Group: admins
    |
    |-- Policy: AdministratorAccess
    |
    |-- IAM User: siddharth-admin
    |-- IAM User: user-02
    |-- IAM User: user-03
```

### Why Use Groups?

Without groups, you might need to attach policies individually to every user.

Suppose a company has 20 developers. Instead of attaching the same permissions to 20 users:

1. Create a `developers` group.
2. Attach the required policies to that group.
3. Add all 20 developers to it.

When a new developer joins, you add them to the group rather than configuring every permission individually.

**Important:**

* Users can belong to multiple groups.
* Users inherit permissions from the policies attached to their groups.
* A group does not have login credentials of its own.

## 6. What Is AdministratorAccess?

`AdministratorAccess` is an AWS-managed IAM policy that grants broad administrative permissions across AWS services.

When attached to the `admins` group, its members receive those permissions through group membership.

### Direct vs Inherited Permissions

* **Direct permission:** A policy is attached directly to the IAM user.
* **Inherited permission:** A policy is attached to a group the IAM user belongs to.

In the example, the user's administrative access comes from the `admins` group, not from a policy attached directly to the user.

**Security note:** `AdministratorAccess` is extremely broad. Use it only when necessary, especially in production. Follow the principle of **least privilege** by granting only the permissions required for the user's work.

## 7. IAM Tags

Tags are key-value pairs used to add metadata to AWS resources.

Example:

| Key           | Value          |
| ------------- | -------------- |
| `Department`  | `Engineering`  |
| `Environment` | `Development`  |
| `Project`     | `DataPipeline` |

Tags can help:

* Organize resources.
* Identify resource ownership.
* Allocate costs.
* Support access-control strategies when policies use tags.

Tags are optional during user creation.

## 8. AWS Account ID and Sign-in URL

Each AWS account has a unique account ID, usually a 12-digit number.

IAM users can sign in using an AWS account sign-in URL, which can contain the account ID or a custom account alias.

### What Is an Account Alias?

An **account alias** is a human-readable identifier for your account's IAM sign-in URL.

For example, instead of using a long account-specific URL, you might create an alias such as `my-learning-account`.

The alias must be available and unique within AWS's account-alias namespace.

### How to Sign In as an IAM User

1. Open the AWS sign-in page.
2. Select **IAM user** sign-in.
3. Enter your account ID or account alias.
4. Enter the IAM username.
5. Enter the password.

The account ID identifies the AWS account, while the username identifies the IAM user within that account.

## 9. Using Two AWS Identities in the Browser

The lesson demonstrates keeping two browser windows open:

* Normal browser window: Root user.
* Private/incognito window: IAM user.

This allows both identities to stay signed in simultaneously because they have separate browser sessions.

This approach is useful when testing permissions or comparing root and IAM access.

**Caution:** Keep root credentials and recovery options secure. Do not share passwords, and enable MFA on the root user.

## 10. Key Concepts for the Exam

| Concept                       | Remember This                                              |
| ----------------------------- | ---------------------------------------------------------- |
| IAM                           | Manages identities and access permissions                  |
| IAM is global                 | No Region selection is required                            |
| Root user                     | Full account access; avoid routine use                     |
| IAM user                      | Identity with assigned permissions                         |
| IAM group                     | Collection of users sharing permissions                    |
| IAM policy                    | Defines allowed or denied actions                          |
| AdministratorAccess           | Broad administrative permissions                           |
| Autogenerated password        | Initial password generated by AWS                          |
| Password reset at first login | User replaces the initial password                         |
| Tags                          | Optional key-value metadata                                |
| Account alias                 | Human-readable sign-in identifier                          |
| Least privilege               | Grant only the permissions required                        |
| IAM Identity Center           | Recommended option for centrally managing workforce access |


## 12. Final Takeaway

* **IAM users** represent identities.
* **IAM groups** organize users.
* **IAM policies** define permissions.
* Users inherit permissions attached to their groups.
* IAM is a global service.
* Root access should be reserved for tasks that require it.
* Use groups to simplify permission management.
* Follow least privilege when assigning permissions.
* Use MFA to improve account security.
